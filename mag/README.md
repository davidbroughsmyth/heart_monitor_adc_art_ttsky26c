# Magic layout for heart_monitor_adc

Analog **custom_gds** tile: OpenLane-hardened `sar_digital` child + Magic AFE.

## Do not use the digital local-harden guide here

[Tiny Tapeout local hardening](https://tinytapeout.com/guides/local-hardening/) (`tt_tool.py` + LibreLane on the **top** module) is for digital projects.

This repo:

- Has **no** `tt/` / `tt_tool.py`
- Hardens only `sar_digital` with **OpenLane** Docker
- Assembles the **2×2** tile in Magic and commits `gds/` + `lef/`
- CI uses `tt-gds-action/custom_gds` (packs checked-in GDS; does not reharden)

Companion SNN may follow the digital guide; this ADC does not.

## Prerequisites

- Docker
- Local sky130A PDK via **volare** (default `PDK_ROOT` in Makefile)
- Image: `efabless/openlane:…-arm64v8` (`--platform linux/arm64`). On amd64 hosts, switch the image tag.

## Targets

```sh
make top         # build the 2×2 connected tile (dense AFE + macro + routing) → ../gds ../lef
make update_gds  # == make top
make top-verify  # rebuild + hierarchical extract → top_hier.spice (connectivity check)
make harden      # OpenLane flow for sar_digital only
# legacy 1×2 metal-only placeholder flow (reference only):
make start ; make afe ; make integrate
```

`build_top_2x2.tcl` is the current flow: it imports the TT **2×2** analog
template (`tt_analog_2x2.def`, die **334.88 × 225.76 µm**), places the dense AFE
(`afe_analog_dense`, bottom) and the hardened `sar_digital` macro (top), then
routes the full analog interface in the channel between them.

### After `make harden`

Copy results into the macro tree (Makefile does **not** do this automatically). Committed macro may come from tag `harden_met4`:

```sh
TAG=harden   # or harden_met4
cp openlane/sar_digital/runs/$TAG/results/final/gds/sar_digital.gds macros/sar_digital/
cp openlane/sar_digital/runs/$TAG/results/final/lef/sar_digital.lef macros/sar_digital/
cp openlane/sar_digital/runs/$TAG/results/final/verilog/gl/sar_digital.v macros/sar_digital/sar_digital.gl.v
make update_gds
```

Design sources for OpenLane live under `openlane/sar_digital/` (keep in sync with `../src/sar_digital.v`).

**Pin placement:** `openlane/sar_digital/config.tcl` sets `FP_PIN_ORDER_CFG` to
`openlane/sar_digital/pin_order.cfg`, which consolidates the **analog-facing pins
(`cmp_out`, `sample`, `dac_bits[11:0]`) on the south edge** (facing the AFE strip)
and keeps digital I/O (`clk`, `rst_n`, `uo_out`, `uio_out`, `uio_oe`) on the north
edge. This replaced the earlier split-edge `dac_bits` placement that made AFE
routing intractable. Re-harden with `make harden`, then copy artifacts as below.

## Constraints

- **No user met5** — reserved for TT power grid ([analog specs](https://tinytapeout.com/specs/analog/))
- Digital child: `RT_MAX_LAYER=met4`
- Do not paint met4 horizontally across both `VDPWR` and `VGND` stripes

## AFE — connected real-device cells (LVS-clean)

The AFE is now built from **real `sky130_fd_pr` Magic gencells** (not metal
placeholders) and is **LVS-clean vs the schematic**. Each cell is generated by a
TCL script and verified by `verify_afe.sh` (build → extract → signoff DRC via GDS
round-trip → netgen LVS against `analog/sky130/`):

| Cell (`mag/`) | Contents | LVS vs | Result |
|---|---|---|---|
| `afe_sh.tcl` → `afe_sh` | TG sample/hold + MIM hold cap | `sample_hold.spice` | Circuits match uniquely |
| `afe_cmp.tcl` → `afe_cmp` | diff-pair comparator (11 FETs) | `comparator.spice` | Circuits match uniquely |
| `afe_slice.tcl` → `afe_slice` | one R-2R bit slice (proof) | `dacslice.spice` | Circuits match uniquely |
| `afe_dac.tcl` → `afe_dac` | **full 12-bit R-2R DAC**, single row (72 FET + 24 poly R) | `cdac_12b.spice` | Circuits match uniquely |
| `afe_dac_folded.tcl` → `afe_dac_folded` | same DAC **folded into 2 rows** (186 × 75 µm) | `cdac_12b.spice` | Circuits match uniquely |
| `afe_analog.tcl` → `afe_analog` | **connected AFE** (S/H + cmp + DAC), single row (~400 × 66 µm) | `sar_afe.spice` | Circuits match uniquely |
| `afe_analog_folded.tcl` → `afe_analog_folded` | **connected AFE folded into 2 rows** (253 × 78 µm) | `sar_afe.spice` | Circuits match uniquely |
| `afe_analog_dense.tcl` → `afe_analog_dense` | **dense** folded AFE — same netlist, tighter 0.5 µm track pitch + closer rows (**253 × 44 µm**) | `sar_afe.spice` | Circuits match uniquely |

- **DAC is R-2R** with real **`sky130_fd_pr__res_xhigh_po_0p35`** poly resistors
  (2R drawn 3.5 µm → `l=3.34`, R drawn 1.75 µm → `l=1.59`; guard rings tied to
  `gnd`). `analog/sky130/cdac_12b.spice` was updated to instantiate these so the
  extracted layout matches under netgen (which compares poly resistors by device
  + `l`/`w`, not ohms). Both SPICE benches still PASS.
- **Routing style:** one horizontal met2 track per net + met1 risers from each
  device's own pad (channel route). This is *short-free by construction* — which
  is why the blocks reach LVS-clean — but it is **area-inefficient**. The
  single-row `afe_analog` is ~**400 × 66 µm** (does not fit the 161 × 73 µm bottom
  strip). **Folding the DAC into two device rows** (`afe_dac_folded`,
  `afe_analog_folded`) shrinks the width dramatically: `afe_analog_folded` is
  **253 × 78 µm**, which fits a **2-tile-wide (≈322 µm)** column.
- **Multi-row placement fix:** device gencells are drawn at the origin then
  translated. The translate must move **vertically first (n) then horizontally
  (e)** — doing `e` then `n` parks a row-B device on top of the row-A device at
  the same x (row B resets the x cursor), merging their tiles so the second move
  drags the neighbour's `nmos`/`pmos` recognition markers away (the device then
  disappears and everything shorts). The empty `x=0` column makes `n`-then-`e`
  always overlap-free. Fixed in `afe_lib.tcl` (`afe::fet`/`afe::res`/`afe::cap`).
- **DRC:** signoff DRC reports only benign **`met1.6` (metal1 min-area)** tiles
  that come from the gencells' own `full_metal` gate pads (a bare device already
  reports them); there are **no real spacing/short violations**.
- Reusable helpers live in `afe_lib.tcl` (`afe::fet`, `afe::res`, `afe::cap`,
  channel-route risers/vias). Run any cell:

```sh
BUILD_TCL=afe_analog.tcl ./verify_afe.sh afe_analog /work/analog/sky130/sar_afe.spice sar_afe
```

Run the folded AFE:

```sh
BUILD_TCL=afe_analog_folded.tcl ./verify_afe.sh afe_analog_folded /work/analog/sky130/sar_afe.spice sar_afe
```

## Connected 2×2 top (`build_top_2x2.tcl`) — DRC-clean + connectivity-verified

The AFE is now **placed and routed to the `sar_digital` macro** in a real 2×2 tile:

- **Density:** the folded AFE's one-track-per-net channel route is height-bound.
  `afe_analog_dense` keeps the exact folded netlist but tightens the met2 track
  pitch (1.0 → **0.5 µm**) and pulls the two device rows together (`YB` 44 → 24),
  shrinking the cell from 253 × 78 µm to **253 × 44 µm**. The innermost track
  stays at ±3.0 µm so it clears the tallest device/resistor; only the outer pitch
  tightens, so LVS is unchanged (still *Circuits match uniquely*) and DRC still
  shows only benign `met1.6`.
- **Floorplan:** the tile height (225.76 µm) is fixed for every `xN2` size, so the
  AFE had to get *shorter* (not just narrower) to stack under the 140 µm-tall
  macro with a routing channel. Dense AFE (44 µm) at the bottom + macro at top
  leaves a ~24 µm channel.
- **Routing:** a 2-layer channel router — **met3 verticals + one met4 horizontal
  per net** — connects all 14 signals (`cmp_out`, `sample`, `dac_bits[0..11]` ↔
  AFE `cmp_out`/`sample`/`b0..b11`), plus `vin_ecg`→`ua[0]`, `vref`→`ua[1]`,
  `gnd`→`VGND`, `vdd`→`VDPWR` (the vdd run hops under the VGND stripe on met3 to
  avoid a met4 short).
- **Verified:** signoff DRC = 257 tiles, **all benign `met1.6`** (no real
  violations); hierarchical extraction (`make top-verify` → `top_hier.spice`)
  confirms every AFE pin merges with the correct macro pin / `ua` pin.

### Not done (follow-on)

- **Digital boundary I/O** (`clk`, `rst_n`, `uo_out`, `uio_out`, `uio_oe`) and the
  macro `VPWR`/`VGND` rails are left to the TT tile power grid / best-effort (the
  boundary pins are imported from the template); full digital-to-boundary routing
  is not done.
- Full-tile netgen LVS (top layout vs the complete gate + AFE netlist) and 12-bit
  INL/DNL/metrology remain out of scope.

**Do not flatten** the `.mag` / GDS — keep `sar_digital` as a child cell
([TT Mag note](https://tinytapeout.com/specs/analog/)).
